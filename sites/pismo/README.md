# Письмо

Интерактивная почта для кейса VK Tech Hackathon «Семантический поиск по личной почте».

В приватной версии Sites два вымышленных ящика. Поиск по словам сравнивает токены, а поиск по смыслу дополнительно использует словарь выражений и тематическую разметку вымышленных писем. В обоих режимах доступны фильтры по отправителю и периоду и поиск по номеру заказа.

«Спросить» разбирает запрос на текст и поддерживаемые поля поиска, затем показывает выдержки и источники. Для вопросов о сроке и сумме ответ появляется, если найдено подходящее свидетельство в тексте или карточке письма. Обработка выполняется в интерфейсе без внешнего LLM API. По ссылке на источник письмо открывается рядом с ответом.

Напоминания в Sites хранятся в D1 по идентификатору пользователя и почтовому ящику. Интерфейс сравнивает сохранённый срок с текущим временем и отмечает сработавшие записи в папке «Напоминания». Метки избранного, прочитанного и архива хранятся в браузере.

В Refero взяли [поиск и фильтры Missive](https://refero.design/flows/6274), [ответ с источниками Parallel](https://refero.design/flows/9073) и [выбор времени Missive](https://refero.design/flows/6281).

## Локальное демо

Из этой папки выполните команды в Node.js 22.13+ и откройте http://127.0.0.1:8941/. Локальный Worker использует SQLite в `.preview/`.

```bash
node scripts/build.mjs
node scripts/preview.mjs
```

## Подключение архива хакатона

Запустите сервер из корня репозитория `vk-mail-search` и откройте http://127.0.0.1:8940/. По умолчанию сервер подхватывает интерфейс из `sites/pismo/dist` и архив из `data/mipt_mail_search_participants.zip`. Если файлы лежат отдельно, укажите `--dist` и `--archive`.

Для проверки на ноутбуке достаточно Python 3.10+ и BM25.

```bash
python3 -m mail_search.web --archive /path/to/mipt_mail_search_participants.zip --lexical-only
```

Для E5 и BGE на GPU используйте существующее окружение проекта. Укажите один свободный GPU и пути к базовым моделям и дообученным весам.

```bash
CUDA_VISIBLE_DEVICES=<gpu-id> python -m mail_search.web \
  --archive /path/to/mipt_mail_search_participants.zip \
  --e5-model models/e5-small-614241f \
  --bge-model models/bge-reranker-v2-m3-953dc6f \
  --bge-weights runs/compare-r1/bge-returns/best-finetuned.safetensors
```

В режиме «По смыслу» E5 строит индекс для выбранного ящика при первом запросе. BGE пересортировывает до 50 кандидатов. Следующие запросы используют готовые embeddings ящика из памяти процесса. Дату запроса можно изменить в шапке. Она задаёт срез почтового ящика и точку отсчёта для «вчера». Сервер слушает только loopback. Если он запущен на сервере, используйте SSH port forwarding.

Сервер корпуса хранит напоминания в отдельном файле SQLite. Путь можно переопределить флагом `--reminders-db`. В пакет Sites входят интерфейс, Worker и схема базы. Данные архива и веса моделей остаются в окружении корпуса.

## «Спросить» с DeepSeek через OpenRouter

В режиме «Авто» справа открывается чат. Jev 1.14 через OpenRouter Decisions выбирает маршрут по текущему запросу и, для уточнения, тексту предыдущего поиска. Для списка писем чат показывает результат поиска. Вопросы, смешанные задачи, просьбы о действии и случаи с уверенностью ниже 0,70 идут ассистенту. При ошибке API маршрут определяют правила браузера. «Поиск» и «Спросить» пропускают классификацию. После ручного поиска можно переключить режим или нажать «Спросить» над результатами. Последний запрос и его выдача появятся в чате. Смена ящика или даты обнуляет контекст.

Режим с моделью включается флагом `--openrouter-env` для уже заданного `OPENROUTER_API_KEY` или флагом `--openrouter-key-file` для файла владельца с правами `600`. Запросы идут в DeepSeek V4.1 Flash через OpenRouter с включённым ZDR. За вопрос выполняется до двух вызовов. Сервер принимает от модели поисковую формулировку и номера выдержек. Тексты цитат из письма и события напоминаний обрабатываются приложением. Напоминание сохраняется при явном подтверждении в диалоге.

Ассистент просматривает до 16 писем из выдачи и показывает до трёх выдержек. Хронология по одному номеру показывает распознанные статусы со ссылками на исходные письма. Просьба о действии в открытом диалоге использует уже найденные письма. Черновик можно изменить и скопировать. Он хранится в текущем диалоге и не отправляется автоматически.

Чтобы использовать уже запущенный сервис E5 + BGE на H200, укажите порт локального SSH-перенаправления. `--upstream-port` использует H200 для семантического поиска и хранения напоминаний. Точный поиск по идентификаторам архива `SYN-…` использует локальную копию архива. Пример запуска с локальным OpenRouter и H200 на порту 8947.

```bash
python3 -m mail_search.web --archive /path/to/mipt_mail_search_participants.zip \
  --port 8949 --upstream-port 8947 --openrouter-env \
  --assistant-limit 20 --reminders-db runs/pismo/openrouter-browser.sqlite3
```

SQLite хранит отдельные лимиты DeepSeek и Jev между запусками. При исчерпании лимита, отсутствии ключа или ошибке соответствующей модели используются локальные правила. В браузере решения Jev помечаются в чате, а ответы с моделью подписаны «Источники подобрал DeepSeek».

Проверка маршрутизации использует два фиксированных набора синтетических русскоязычных запросов. Команда вызывает платный Decisions API по одному разу на запрос и сравнивает Jev с правилами браузера.

```bash
python3 -m mail_search.eval_intent --output runs/pismo/jev-routing.json
python3 -m mail_search.eval_intent --cases configs/jev-routing-holdout.jsonl \
  --output runs/pismo/jev-routing-holdout.json
```

## Условное напоминание

Добавьте `--condition-checks 12` к команде запуска с OpenRouter, чтобы включить условные напоминания с отдельным бюджетом проверок Jev. В открытом письме нажмите «Напомнить о письме» и выберите «Только если подтверждение не придёт». Опишите один факт, который должен быть подтверждён в новом письме. Ключи из исходного письма можно изменить. Все указанные ключи должны встречаться в письме-кандидате. Если ключей нет, по тексту условия отбираются до шести кандидатов.

В чате можно написать «Напомни 15 сентября в 9:00, если машина за контейнером SYN-bc98b422f6 ещё не приехала». Если найдено несколько исходных писем, выберите нужное. Сервер читает ключи из полного исходного письма, а сохранённые правки ключей подставляются при повторном открытии. Чат заполняет форму. Запись появляется после нажатия «Сохранить». Нераспознанный срок можно ввести в форме.

Сервер хранит срок и условие в локальной SQLite. При смене среза ящика он заново определяет состояние, переиспользуя закэшированные решения по ранее просмотренным письмам. Jev получает ограниченные отрывки, выбирает статус и строку-основание. При уверенном подтверждении напоминание остаётся в папке со ссылкой на письмо. Проверка обходится без DeepSeek. Обычные напоминания продолжают использовать текущее время. Условные в этом демо используют даты получения из архива. Подтверждение с датой получения в день напоминания обрабатывается консервативно, поскольку у почтового среза нет времени получения.

Для демонстрации выберите ящик 03 и дату 12 сентября 2028. Найдите `SYN-bc98b422f6`, откройте письмо о создании автовизита и задайте условие «Грузовик уже приехал на терминал за контейнером» со сроком 15 сентября. На срезе за 13 сентября напоминание останется активным, а на срезе за 14 сентября появится подтверждение. В обоих срезах понадобятся ключи контейнера и клиента, которые подставляются из письма об автовизите.
