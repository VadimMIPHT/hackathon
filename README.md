## Запуск в VS Code

Открывать нужно **папку `smartmail-baseline`**, а не родительский
каталог: пути `--data data` относительные.

1. `code smartmail-baseline` (или File → Open Folder → выбрать
   `smartmail-baseline`).
2. Если расширение Python не установлено, VS Code предложит поставить
   его из `.vscode/extensions.json` — согласиться.
3. `Ctrl+Shift+P` → **Python: Select Interpreter** → выбрать Python 3.13
   из miniconda (на этой машине `/home/alvaro-sann/miniconda3/bin/python`)
   или любой другой Python 3.10+. Внешних зависимостей нет.
4. `F5` → выбрать конфигурацию:
   - **evaluate: dev + абляция** — метрики и сравнение вариантов;
   - **evaluate: dev** — только основные метрики;
   - **demo: отклонённые платежи** — пример выдачи по одному запросу;
   - **unittest: все тесты** — 65 тестов под отладчиком.
5. Панель Testing (иконка колбы) → **Run All Tests**: конфигурация
   unittest уже прописана в `.vscode/settings.json`.
6. `Ctrl+Shift+B` — быстрый запуск `evaluate` без отладчика
   (задача из `.vscode/tasks.json`).
7. Или в интегрированном терминале (View → Terminal):

```bash
python3 evaluate.py --data data --ablation
python3 -m unittest discover -s tests -v
```

Точки останова работают в `evaluate.py`, `demo.py` и в тестах.
Если при импорте пишет `No module named smartmail`, значит открыта не
та папка: корнем workspace должен быть `smartmail-baseline`, где лежит
пакет `smartmail/`.
Если VS Code не знает тип конфигурации `debugpy` (старое расширение
Python), замените `"type": "debugpy"` на `"type": "python"` в
`.vscode/launch.json`.

## Аугментация данных

Dev-набор — 99 запросов одного шаблона «тип письма + дата». Для файнтюна
би-энкодера и проверки устойчивости к перефразировкам этого мало, поэтому
есть генератор синтетических запросов: [smartmail/augment.py](smartmail/augment.py)
и [scripts/augment.py](scripts/augment.py).

Генерируются запросы, а не письма: 16k документов достаточно для retrieval,
а синтетические письма только добавляют шум в индекс. Положительный документ
у сгенерированного запроса известен по построению.

```bash
# без сети: шаблонный fallback, проверить пайплайн
python3 scripts/augment.py --data data --out data_aug \
    --backend template --limit 300 --per-email 6

# OpenAI-совместимый API, ключ только в переменной окружения
export OPENAI_API_KEY=...
python3 scripts/augment.py --data data --out data_aug \
    --backend openai --model gpt-4o-mini --limit 2000 --per-email 5 --negatives 10

# локальная Ollama
python3 scripts/augment.py --data data --out data_aug \
    --backend ollama --model qwen2.5:7b --limit 2000
```

Результат: `data_aug/queries.jsonl`, `qrels.jsonl`, `pairs.jsonl` (с hard
negatives), `summary.json`. Каталог `data_aug/` не коммитится — это
генерируемые данные.

Проверка на аугментированном наборе:

```bash
python3 evaluate.py --data data \
    --queries data_aug/queries.jsonl --qrels data_aug/qrels.jsonl --split aug
```

Что важно понимать:

- qrels синтетические, по одному положительному на запрос, поэтому
  `Recall@10` здесь — это Hit@10 и нижняя оценка. Сравнивать с dev нельзя.
- шаблонный backend — только проверка пайплайна: запросы получаются близкими
  к теме письма и почти не проверяют пересказ смысла. Для реальной
  аугментации нужен LLM-backend.
- дедупликация идёт по тексту запроса: одинаковые формулировки из разных
  писем схлопываются, иначе метки противоречат друг другу.
- на шаблонном backend BM25 даёт R@10 ≈ 0.61 против 0.90 на dev: без даты
  и с общими формулировками письмо трудно отличить от похожих. Это аргумент
  за dense-ретривер и за более конкретные запросы от LLM.

### Кластеры и честные метрики

Сгенерированный запрос часто описывает группу похожих писем, а не одно.
В корпусе медиана одинаковых тем в ящике — 18 писем (p90 1712), поэтому
метрика с одним положительным занижает результат: без номера заказа или
даты две «Успешная оплата» неразличимы, да и пользователю всё равно, какая
из них в выдаче.

`scripts/cluster_eval.py` строит near-duplicate кластеры (ящик + тема;
строгий режим — ещё и скелет тела с заменами чисел на `#`), считает
cluster hit@10 / P@10 / MRR и вычищает false negatives:

```bash
python3 scripts/cluster_eval.py --data data --pairs data_aug/pairs.jsonl \
    --out data_aug --filter-negatives
```

На шаблонном наборе: single hit@10 0.611, cluster hit@10 0.912, P@10 0.556.
С `SearchEngine(..., subject_boost=2)` — 0.689 / 0.944 / 0.581, при этом
на dev метрики не меняются (R@10 0.904, nDCG 0.962). Фильтр убирает около
половины BM25-негативов как false negatives — использовать их в обучении
нельзя.

**Кластеризация — не замена ранжированию.** Роутинг запроса в кластер
сужает кандидатов, но внутри кластера всё равно нужен сигнал (номер,
сумма, дата), чтобы выбрать конкретное письмо. Кластеры полезны для
меток, негативов и дедупликации выдачи.

## Гибридный слой: dense + RRF, query expansion, группировка

`smartmail/dense.py` — e5-small в ONNX-квантовке (118 МБ, 384 измерения,
без torch). `smartmail/hybrid.py` — BM25 + dense через Reciprocal Rank
Fusion, RM3-расширение запроса, дедупликация near-duplicate писем,
стратификация выдачи по отправителю/теме и жёсткий фильтр, если в запросе
явно указан отправитель.

Модель и окружение (один раз):

```bash
python3 -m venv .venv
.venv/bin/pip install numpy tokenizers onnxruntime

mkdir -p .models/multilingual-e5-small/onnx
curl -L -o .models/multilingual-e5-small/onnx/model_quantized.onnx \
  https://huggingface.co/Xenova/multilingual-e5-small/resolve/main/onnx/model_quantized.onnx
curl -L -o .models/multilingual-e5-small/tokenizer.json \
  https://huggingface.co/Xenova/multilingual-e5-small/resolve/main/tokenizer.json
curl -L -o .models/multilingual-e5-small/config.json \
  https://huggingface.co/Xenova/multilingual-e5-small/resolve/main/config.json
```

Запуск (эмбеддинги кэшируются в `.cache/`):

```bash
.venv/bin/python scripts/hybrid_eval.py --data data --split dev
.venv/bin/python scripts/hybrid_eval.py --data data \
    --queries data_aug/queries.jsonl --qrels data_aug/qrels.jsonl --split aug
```

Замеры на dev (7 ящиков из запросов, 9 949 писем):

| Вариант | R@10 | nDCG@10 | MRR@10 | p99 |
| --- | ---: | ---: | ---: | ---: |
| BM25 | 0.903 | 0.963 | 0.983 | 1.2 мс |
| BM25 + RM3 | 0.901 | 0.920 | 0.914 | 2.6 мс |
| hybrid (RRF) | 0.889 | 0.947 | 0.962 | 13.5 мс |
| hybrid + RM3 | 0.898 | 0.947 | 0.964 | 17.9 мс |
| hybrid + dedup + strat | 0.807 | 0.874 | 0.965 | 17.3 мс |

На 412 аугментированных запросах: BM25 0.551, BM25+RM3 0.481,
hybrid 0.434, dense-only 0.318, dedup+strat 0.342. Zero-shot e5-small
на этом распределении **хуже BM25**: запросы короткие и шаблонные, а
dense путается в near-duplicate письмах. RRF с равными весами тянет
сильный список вниз; уменьшение веса dense тоже не даёт прироста.
Слой оставлен как заготовка под файнтюн: включать в прод имеет смысл
только после того, как dense-only начнёт обгонять BM25.

Дедуп и стратификация — это слой представления, а не ранжирования:
на dev, где релевантны десятки одинаковых писем, они ожидаемо роняют
Recall. Считать метрики нужно до дедупа, а схлопывать уже готовую выдачу.

## Как устроено

Четыре слоя, каждый можно заменить независимо:

1. **Метаданные — ящик и доступность.** Поиск идёт только внутри
   `synthetic_user` запроса. Письма с `doc_dt` позже `query_date`
   недоступны по условию задачи; письма с `doc_dt = null` не могут
   подтвердить попадание в конкретный день и при точном фильтре
   отбрасываются.
2. **Дата или диапазон.** «вчера», «накануне», «последний день января»,
   «9 или 10 октября», «с 30 января по 2 февраля», «25–27 сентября»,
   «N дней/недель/месяцев назад», точные даты. Найденный фрагмент
   вырезается из запроса, чтобы не засорять BM25. Срез — 1–262 письма.
3. **BM25 по срезу.** `k1=1.5`, `b=0.75`, IDF по всему корпусу. При
   маленьком срезе точный перебор быстрее и точнее любого ANN, поэтому
   FAISS/HNSW здесь не нужны.
4. **Текст.** NFKC, нижний регистр, `ё -> е`, снятие HTML/URL,
   стоп-лист, доменные синонимы в запросе (`отказ`/`отклон`,
   `погруз`/`погруж`, `сбо`/`ошибк`). Стеммер — Snowball Russian;
   сверен с эталонной реализацией `snowballstemmer` на всех 11 290
   уникальных словах корпуса (0 расхождений). Поверх стема
   индексируется 6-символьный префикс слова длиннее 7 символов —
   страховка от того, что Snowball разводит формы одного корня
   (`отклонена -> отклон`, `отклонённых -> отклонен`).

## Главная находка по данным

Исходные 99 публичных запросов — шаблонные «<тип письма>, полученные
<дата>», поэтому на них метрика почти насыщена фильтром по дате
(`date_only` даёт nDCG 0.663). Расширенные 40 запросов — перефразировки
и диапазоны: там другая лексика («отказ» вместо «операция отклонена»)
и несколько дней. На них BM25 без синонимов проседал до R@10 0.42,
после разбора диапазонов и словаря синонимов — 0.52 при nDCG 0.952:
нужное письмо обычно находится, но точная формулировка всё ещё мешает.

Дальнейший рост — за счёт файнтюна dense/кросс-энкодера на
`pairs_clean.jsonl`. Zero-shot e5-small, который тоже пробовали, на этом
распределении оказался хуже BM25 (подробности в разделе про гибрид).

## Ограничения

- Смысловые запросы без даты обрабатываются BM25 по всему ящику —
  это осознанно слабое место; zero-shot dense не помог, следующий шаг —
  файнтюн би-энкодера.
- Чередование согласных лечится только словарём синонимов
  («погрузка»/«погружен», «отказ»/«отклонена»); новые пары придётся
  добавлять руками.
- Поддержаны точный день, диапазоны («с 1 по 5», «9 или 10», «25–27»)
  и относительные «N назад». Не парсятся месяц целиком («за октябрь»)
  и «в начале месяца».
- `doc_dt = null` (433 письма) не участвуют в поиске по конкретному дню.
- Нет сниппетов с подсветкой, пагинации, учёта тредов и дублей.

## Куда наращивать

- **Dense-ретривер** (multilingual-e5 / USER-bge-m3) по тому же срезу
  или по всему ящику, слияние с BM25 через RRF. Контракт уже готов:
  `SearchEngine.search()` возвращает `doc_id -> score`, слияние
  добавляется отдельным слоем.
- **Кросс-энкодер** на топ-40–60 кандидатов — второй по величине рычаг.
- **Месяц/квартал целиком** и мягкий буст по дате вместо жёсткого фильтра.
- **Обёртка FastAPI** с прогревом моделей на старте: p99 < 1 с считается
  вместе с сетью до браузера, но без рендера.
