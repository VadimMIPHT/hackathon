# Статистика и воспроизводимость

Запрос — единица усреднения для качества. Метрики усреднены с равным весом запросов. Все методы обрабатывают одинаковые запросы и применяют одинаковые ограничения по ящику и дате. BM25 использует слова с двойным весом темы, без стемминга. При отсутствии лексического совпадения он может вернуть меньше K писем. E5 оценивает все допустимые письма по косинусному сходству. RRF суммирует обратные позиции с k=60 для 50 кандидатов от каждого метода.

nDCG учитывает позиции бинарных релевантных документов. Recall делит количество релевантных среди первых K на все размеченные релевантные письма. MRR@10 использует позицию первого релевантного на запросах с одним целевым письмом. Больше лучше для всех трёх. Отсутствие qrel считается нулевой релевантностью по README архива. Письма совпадают по `synthetic_user`, а при известной дате должны быть доступны на `query_date`. День из текста дополнительно ограничивает выдачу и отсекает письма без известной даты. При нераспознанном дне остаётся ограничение `as_of`.

## Парные разности E5 и сравниваемого метода

| train | as_of | BM25 | +0.1695 | 26 / 26 / 3 |

| train | query_day | BM25 | +0.6886 | 48 / 3 / 4 |

| val | as_of | BM25 | +0.1577 | 13 / 5 / 3 |
| val | as_of | BM25 + E5 (RRF) | +0.0198 | 10 / 6 / 5 |
| val | query_day | BM25 | +0.3050 | 13 / 8 / 0 |
| val | query_day | BM25 + E5 (RRF) | +0.1328 | 8 / 11 / 2 |

Почтовый ящик — единица группировки зависимости. В val только два размеченных ящика, в train три. Повторяемость точной выдачи проверена двумя запусками на val. Эти повторы не увеличивают число независимых ящиков. Статистические тесты и доверительные интервалы для обобщения на новые ящики не рассчитывались. Разбивка по ящикам показывает наблюдаемый разброс.

## Конфигурация

- Архив `mipt_mail_search_participants.zip`, SHA-256 `2df885f77be8f8aa750b484439fc99dfc2a401fce53306160c03ad95cae0de03`. Все контрольные суммы внутри архива совпали. Seed разбиения `42`.
- Базовый коммит репозитория `0f47058c0da551eedf9270b3c7eb513d624dac3d`. Реализация лежит в локальных изменениях. SHA-256 каждого Python-файла и манифеста сплитов в JSON совпадают с текущими файлами.
- E5 `intfloat/multilingual-e5-small` ревизии `614241f622f53c4eeff9890bdc4f31cfecc418b3`. Ограничение 256 токенов, FP16, mean pooling и нормализация FP32.
- NVIDIA H200, Python 3.11.18, PyTorch 2.10.0+cu128, CUDA 12.8, Transformers 4.57.6, tokenizers 0.22.2, NumPy 2.2.6. Один GPU, до двух потоков PyTorch/BLAS, без установки зависимостей.
- Офлайн-задержка включает фильтрацию, скоринг и слияние при необходимости. Эмбеддинги документов считаются заранее. На 21 val-запросе nearest-rank p99 равен максимуму наблюдений. Нагрузочный тест серверного API предстоит измерить отдельно.
